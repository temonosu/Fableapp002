# 要件定義: deploy(Google Cloud への低コストデプロイ)

> ステータス: **確定**

## 概要

「花札行脚(仮)」を Google Cloud 上で **できるだけ安く**(理想は無料枠内)公開する。
個人開発・フレンド対戦規模のトラフィックを想定し、運用の手間も最小にする。

## 機能要件

### 要件1: 単一サービスでの公開

**ユーザーストーリー:**
開発者として、1つの URL でゲーム(SPA)と API(シグナリング)を公開したい

**受け入れ基準:**

1. WHEN 利用者が公開 URL にアクセスした THEN front のビルド済み SPA が配信 SHALL される
2. WHEN SPA のクライアントルート(/run, /match, /pvp)を直接開いた
   THEN index.html にフォールバックして SPA が起動 SHALL する
3. WHEN /api/v1/* にアクセスした THEN FastAPI が応答 SHALL する
   (同一オリジンのため CORS 設定は不要)
4. WHEN P2P 対戦のシグナリング WS に接続した THEN 対戦の確立が機能 SHALL する

### 要件2: コスト最小化

**ユーザーストーリー:**
開発者として、誰も遊んでいない時間の課金をゼロにしたい

**受け入れ基準:**

1. WHILE アイドル(リクエストなし)THEN インスタンス数は0にスケール SHALL する
2. WHILE 稼働中 THEN インスタンスは最大1・メモリ256Mi を上限 SHALL とする
   (インメモリのルーム台帳が複数インスタンスで壊れないための制約でもある)
3. IF DB が不要な機能構成(現状)THEN Cloud SQL 等の常時課金リソースを
   作成しない SHALL(データ永続化が必要になったら別途 spec を書く)

### 要件3: 再現可能なデプロイ手順

**受け入れ基準:**

1. WHEN 開発者が `./infra/gcp/deploy.sh <PROJECT_ID>` を実行した
   THEN ビルドからデプロイまで完了 SHALL する(リージョン・サービス名は変数)
2. WHEN 同じコマンドを再実行した THEN 新しいリビジョンに置き換わる SHALL

## 非機能要件

| 項目 | 要件 |
|------|------|
| 想定コスト | アイドル時 ¥0。軽い利用は Cloud Run / Cloud Build の無料枠内(月数円以下) |
| リージョン | 既定 asia-northeast1(東京)。変数で変更可 |
| シグナリング | WS 接続がルーム待機中に切れないよう、リクエストタイムアウトを 3600 秒にする |

## スコープ外

- CI からの自動デプロイ(Workload Identity 連携)— 手動デプロイで開始し、必要になったら追加
- 独自ドメイン・CDN
- DB(Cloud SQL / AlloyDB 等)と Alembic の本番適用 — 永続化機能の spec とセットで
- TURN サーバー
