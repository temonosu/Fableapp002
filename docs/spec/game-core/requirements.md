# 要件定義: game-core(こいこい対局エンジン)

> ステータス: **確定**

## 概要

「花札行脚(仮)」の中核となる、こいこいの1局〜賭場戦(持ち文の削り合い)を扱う
対局エンジン。UI・通信から独立した決定論的なロジックとして front 内に実装し、
対AI戦・P2P対戦・観戦・リプレイすべての土台になる。

## 用語

| 用語 | 意味 |
|------|------|
| 局 | 配札から上がり/流局までの1ゲーム |
| 賭場戦 | 複数局を通じた持ち文(チップ)の削り合い。どちらかが0文になるまで |
| レート | 賭場ごとの換算率(文/点)。精算はすべてレートを乗じる |
| 局倍率 | こいこい宣言で上がる倍率。両者共有(×1 → ×2 → ×3 …) |
| 旬札 | 対局時の「月」に対応する札4枚 |
| 細工 | 特定の札に付与される特殊効果。山札に入るため両者に発動しうる |

## 機能要件

### 要件1: 札と配札

**ユーザーストーリー:**
プレイヤーとして、本家花札と同じ48枚の札で遊びたい

**受け入れ基準:**

1. WHEN エンジンを初期化した THEN システムは12ヶ月×4枚=48枚の札
   (光5・タネ9・短冊10・カス24)を提供 SHALL する
2. WHEN 局を開始した THEN システムはシード付き乱数で山札をシャッフルし、
   手札8枚×2・場札8枚・山札24枚を配る SHALL する
3. IF 配札時に場に同月4枚、またはいずれかの手札に同月4枚がある
   THEN システムは配り直す SHALL する(手役は不採用のため)
4. WHEN 同一シードで局を再現した THEN システムは完全に同じ進行を再現 SHALL する

### 要件2: 手番の進行

**ユーザーストーリー:**
プレイヤーとして、本家こいこいのルールで札を取りたい

**受け入れ基準:**

1. WHEN 手番が来た THEN プレイヤーは手札1枚を場に出し、同月の場札があれば
   1枚選んで両方を取り札にできる SHALL(場に同月3枚なら4枚まとめ取り)
2. IF 出した札と同月の場札がない THEN その札は場に残る SHALL
3. WHEN 手札の処理が終わった THEN システムは山札から1枚めくり、
   同様の合わせ処理を行う SHALL(同月2枚あるときは選択を要求する)
4. WHEN 手番終了時に新しい役ができた THEN システムは
   「こいこい」または「勝負」の選択を要求 SHALL する
5. IF 両者の手札が尽きて誰も勝負していない THEN 流局とし、
   無得点で親を交代 SHALL する
6. WHEN 局が終了した THEN 勝者(流局時は前局の親の相手)が次局の親(先手)になる SHALL

### 要件3: 役と精算

**ユーザーストーリー:**
プレイヤーとして、作った役に応じた文数をレートと倍率込みで受け取りたい

**受け入れ基準:**

1. WHEN 取り札が変化した THEN システムは以下の役表で成立役を判定 SHALL する:
   五光10 / 四光8 / 雨四光7 / 三光5 / 花見で一杯5 / 月見で一杯5 /
   猪鹿蝶5 / 赤短5 / 青短5 / タネ1(6枚目以降+1/枚) / タン1(6枚目以降+1/枚) /
   カス1(11枚目以降+1/枚)
2. WHEN 勝負が宣言された THEN 勝者の獲得は
   `役文数合計 × レート × 局倍率 + 旬札ボーナス` SHALL とする
3. WHEN 誰かがこいこいを宣言した THEN 局倍率が +1 される SHALL
   (宣言者を問わず、上がった者がその倍率で受け取る)
4. IF こいこいを宣言していたプレイヤーが上がれずに局が終わった(相手の上がり)
   THEN そのプレイヤーはこいこい料として `場代 × 自分のこいこい宣言回数` を
   追加で支払う SHALL(流局時のこいこい料は発生しない)
5. WHEN 上がった THEN 勝者が取っていた旬札1枚につき `+1文 × レート` を
   加算 SHALL する(局倍率は乗せない)
6. IF 支払いが敗者の持ち文を超える THEN 持ち文全額で打ち止め(飛び)SHALL とする

### 要件4: 賭場戦(持ち文の削り合い)

**ユーザーストーリー:**
プレイヤーとして、賭場ごとの敵と持ち文を賭けて連戦したい

**受け入れ基準:**

1. WHEN 賭場戦を開始した THEN 両者は持ち文を持ち、入場側は場代
   (レート×5文)を支払う SHALL
2. WHEN どちらかの持ち文が0になった THEN 賭場戦は終了 SHALL する
3. WHEN 局と局の間である THEN 入場側プレイヤーは撤退を選択できる SHALL
   (場代は返還しない)
4. IF 入場側の持ち文が場代未満 THEN 首賭けを宣言して入場できる SHALL:
   場代免除・獲得×2・相手の上がりまたは流局で即0文

### 要件5: 細工フック(特殊効果機構)

**ユーザーストーリー:**
開発者として、札の特殊効果(細工)やレリック効果を、エンジン本体を
変更せずに追加したい

**受け入れ基準:**

1. WHEN 対局設定に細工付き札が含まれる THEN エンジンは以下のタイミングで
   効果フックを発火 SHALL する: 札を取った時 / 札を場に出した時 /
   その札を含む取り札で上がった時 / 局終了時の精算時
2. WHEN フックが発火した THEN 効果は純関数として文数増減・局倍率増減・
   情報公開(山札の覗き見等)のいずれかを返す SHALL
3. IF 細工付き札を相手が取った THEN 効果は取った側に発動 SHALL する
4. WHEN 対局ログを再生した THEN 細工の発動を含め同一結果になる SHALL
   (決定論性の維持)

### 要件6: 対AI戦

**ユーザーストーリー:**
プレイヤーとして、NPCと対局したい

**受け入れ基準:**

1. WHEN AIの手番が来た THEN AIは合法手の中から取り札価値・旬・役進行を
   評価して打牌を選択 SHALL する
2. WHEN AIに役ができた THEN AIは局面(残り手数・持ち文・相手の取り札)と
   性格パラメータ(攻撃性0〜1)からこいこい/勝負を判断 SHALL する
3. WHILE AIが思考中 THEN 処理はメインスレッドを長時間(100ms超)
   ブロックしない SHALL

## 非機能要件

- エンジンは UI(React)・通信に依存しない純粋 TypeScript とし、単体テストのみで
  役判定・精算・進行の正しさを検証できること
- 対局の状態遷移はすべて「操作(アクション)」経由で行い、操作ログ+シードから
  局を完全再現できること(P2P同期・リプレイの前提)

## スコープ外

- ラン構造(すごろく盤・市場・熱気・おひねり)→ `roguelike-run`
- P2P通信・観戦 → `p2p-match`
- 手役(手四・くっつき)、月札4枚などのローカル役
- 札のアートワーク(当面はテキスト/記号表現)
